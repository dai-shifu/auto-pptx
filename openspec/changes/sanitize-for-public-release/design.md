## Context

项目已有通用桌面生成流程、共享测试 fixture 构造器及语义一致性测试。公开前检查发现，当前源码与文档包含企业关联名称，测试数据沿用了业务附件编号，Git 跟踪了虚拟环境配置和部分字节码。历史提交中存在已删除的业务附件及作者邮箱。

用户确认公开版本不需要 Git 历史，并要求删除 `CLAUDE.md`，统一使用 `AGENTS.md`。本变更采用最小修改原则，现有暂存删除属于用户工作，必须保留。

## Goals / Non-Goals

**Goals:**

- 让公开源码、示例、规格及归档文档使用通用名称和虚构数据。
- 保留一个有效的 `AGENTS.md`，包含必要开发命令和项目约定。
- 形成独立、经过检查且不包含 Git 元数据的公开源码快照。
- 保持生成逻辑、配置格式、fixture 覆盖范围及测试可重复性。

**Non-Goals:**

- 不删除、重写或重新初始化当前仓库的 `.git`，不修改历史作者信息。
- 不创建或推送 GitHub 仓库，不改进生成算法、GUI 布局或依赖配置。
- 不删除仍有效的 OpenSpec 规格和技术归档来代替脱敏。

## Decisions

### 1. 公开交付使用独立源码快照

在 `dist/public-release/` 下准备源码目录和压缩包，并附上发布步骤与文件清单。该目录已有生成物忽略规则覆盖。快照必须包含最终修改后的实际文件，而不是直接归档仍未包含本次修改的 `HEAD`。

文件清单以当前受版本控制、实际存在的文件为基础，加上经检查的本次新增文件；过滤 `.git`、虚拟环境、字节码、测试缓存、机器配置、已有构建产物和暂存删除文件。使用明确清单导出，避免复制整个工作目录或将导出目录自身再次打包。不要求暂存用户全部修改，也不引入导出框架或新依赖。

发布步骤说明解压后在全新目录初始化仓库、创建首次提交，并由用户选择公开身份和远程地址。快照中保留 MIT 许可证及现有公开署名。相比重写历史，该方案满足用户不保留历史的选择，并让内部仓库继续可用。

### 2. 统一通用名称和开发说明

生成流程模块统一命名为 `src/generator.py`，对应流程测试命名为 `tests/test_generator.py`。只修改文件名、导入、局部别名及必要引用，不调整算法或函数签名，不保留含旧名称的兼容入口。

删除根目录 `CLAUDE.md`。检查其中仍准确且在现有 `AGENTS.md` 中缺失的开发约定，按需合并；不复制失效架构说明或真实业务文件清单。保持标准文件名 `AGENTS.md` 的大小写。

### 3. 文档脱敏覆盖当前保留的全部文档

README、培训文档、`AGENTS.md`、OpenSpec 当前规格和归档均属于公开快照。替换企业名称、真实附件名、实际编号与机器专用路径，使用“批量生成流程”“示例数据”“项目明细”等通用描述；历史技术结论和验收证据继续保留。

本变更新建的提案和验收记录也不得重新列出真实编号、作者邮箱等原始敏感值。现有三张 GUI 截图已检查为通用样例，只有发现遗漏时才替换。通用科学术语、占位符、标准命名空间及公开依赖地址不因关键词匹配而全部删除。

### 4. 示例数据由共享构造器定义

项目编号改成明确虚构的 `DEMO-001`、`DEMO-002`，详情工作表统一使用“项目明细”。同步调整构造器及调用方、断言，重新生成提交的 XLSX；PPTX 仅在其内容或元数据确需修改时重新生成。

继续使用现有语义测试核对提交的二进制 fixture，保留已有数据行数、标题行差异和查找失败等测试场景。新增数据验收关注已知敏感残留和实际 Office 包内容，不用一套新的测试重复实现所有替换规则。

提交的 `config.toml` 使用 `template_column = "模板"`、`header_row = 1` 及通用项目字段；文档示例与之保持一致。运行时默认值和已有用户配置解析逻辑保持不变。

### 5. 清理公开文件集合中的机器产物

停止跟踪虚拟环境配置与已跟踪的 Python 字节码，优先仅移出索引，保留本地环境和缓存可用。补充 `.venv/`、测试缓存及工具本地设置等必要忽略规则，不使用宽泛的 Office 文件忽略规则，以免屏蔽应提交的合成 fixture。

保留用户已有的工具配置和旧流水线暂存删除，不恢复、不改写这些删除。

## Risks / Trade-offs

规格复核补充：用户已确认移除最初方案中的 YAML 配置增量规格，以及旧双 Excel 变更下的六份增量规格。保留这两个变更的历史背景说明并标明其已失效。当前主规格保留二十份，只清理已确认的过时条款；源码、辅助函数及现有测试继续保留。公开包以更新后的规格重新导出。

- [模块改名遗漏动态引用] → 检查全部当前文本和文件名中的旧名称，运行完整 pytest 套件和入口导入检查。
- [文档已经脱敏但二进制仍残留编号或个人信息] → 解包当前 XLSX/PPTX，检查工作表、页面、备注、文档属性、外链和嵌入项；复核保留截图。
- [导出包含旧提交内容或本地文件] → 使用最终工作树明确清单，在独立解压目录检查文件集合与内容，确认无 `.git` 和机器产物。
- [脱敏记录本身暴露原始值] → 公开记录只写处理类别、通用替代值及验证结果，敏感原值不写入提案、测试或发布说明。
- [公开快照包含已清理的 OpenSpec 归档但没有 Git 历史] → 发布说明明确两者区别；归档文本作为当前文档经过相同脱敏检查。

## Migration Plan

1. 清理开发说明、文档和名称引用，完成最小模块重命名。
2. 替换 fixture 示例值、同步二进制及测试断言，清理跟踪的机器文件。
3. 运行完整测试、OpenSpec 严格校验及当前文件和 Office 内容检查。
4. 导出独立快照并解压复核，记录结果和新仓库首次发布步骤。

当前仓库不进行重置、历史清理或推送。需要修正时直接更新当前文件并重新生成快照。

## Open Questions

无阻塞问题。新 GitHub 仓库名称、远程地址和首次提交身份在实际发布时确定，不影响本次脱敏和快照准备。
