## Context

2026-11-18 在 Windows Python 3.12.13 AMD64、Tcl/Tk 8.6.12、Tk scaling 1.3333 下做了三轮独立窗口诊断。首次短文本显示时，外层请求 600×400，内部 Text 实际为 1×1，`displaylines` 返回 95。处理窗口事件后 Text 为 583×400，实际只有 2 行，但窗口高度和滚动条未重新计算。等待 200ms 后仍保持错误高度。此项是实现缺陷。

旧日志还记录首次长文本滚动返回负比例、真实指针测试间歇失败，以及 Tk 加载 `listbox.tcl` 失败。当前该文件存在，三轮诊断的 Tk 初始化均成功，不能据旧日志断定当前安装损坏。原测试的固定 400px、高度 200px 上限及鼠标终点也需要与实际字体、屏幕和布局对照。

补充首次长文本诊断：Text 从 1×1、15000 行变为 583×400、375 行；处理事件并等待 200ms 后，滚动到底的范围为 `(0.9391, 1.0)`。本轮未复现旧日志的负滚动比例。复用窗口显示短文本可得到 600×46、无滚动条，进一步说明首次映射路径与复用路径存在差异；这不代表完整 Windows suite 已通过。

## Goals / Non-Goals

**Goals:** 修复 Windows 首次显示和复用时的布局、滚动；形成跨平台行为测试；查清初始化与真实指针失败。

**Non-Goals:** 不调整无关 GUI、不改变生成和配置、不更换 Tk 或打包工具，不通过删除测试或扩大 skip 范围使验收通过。

## Decisions

1. 保留单个可复用窗口。先应用目标宽度，在 Text 已获得实际像素宽度后计算内容高度，再限制到可用屏幕范围。优先采用受目标和窗口存活检查保护的 Map/Configure 或事件循环回调；实现阶段用最小复现决定具体触发点。单次 `update_idletasks()` 在本机不足；增加固定 sleep 不构成修复。避免在悬停回调中无条件调用完整 `update()` 导致事件重入。
2. 首次显示、长转短、短转长都经过同一尺寸计算。布局阶段保留完整文本，重置顶部视图，并按最终布局决定滚动条。若新增回调，在 hide、目标改变和 destroy 时取消或使其失效。
3. 测试按可观察结果验收。等待实际映射和几何稳定，有明确超时；短文本按实际字体和换行内容判断紧凑高度，长文本验证滚动后最后内容可见。保留默认尺寸回归，但不把 400px 或固定行高规定为跨平台合同。
4. 真实指针测试从当前窗口和单元格的实际边界确定路径，验证能跨入窗口、停留阅读并离开关闭。Windows 有交互桌面时执行；缺少该环境必须报告未验收，不以合成事件替代真实指针结果。避免测试间争用系统指针。
5. Tk 初始化单独诊断。记录解释器、Tk patchlevel、库位置与文件完整性；在独立进程及完整 suite 中复测。只有环境诊断证明缺失时才修复环境。规定 Windows 验收中 GUI 初始化失败或相关测试跳过均不能算通过。

## Risks / Trade-offs

- [延迟布局回调引用旧目标] → 目标或窗口状态校验，覆盖 hide、换行和 destroy 前后的取消行为。
- [滚动条改变宽度后再次换行] → 验证最终宽度和行数稳定，覆盖短长文本交替。
- [DPI、中文字体与屏幕差异] → 按字体和可用屏幕计算预期，在 Windows 默认缩放及另一种缩放下人工复核。
- [修正测试掩盖问题] → 每项测试调整对应 delta spec 场景；保留首次显示、复用、滚动到底和跨窗阅读断言。

## Migration Plan

先更新变更 spec 和复现测试，再做最小布局修复；在 Windows 与 Linux 真实 Tk 下运行相关及完整测试。通过后交给 `optimize-nuitka-build` 验证最终 exe。源码通过不等于成品通过。

## Open Questions

- 首次长文本的负滚动比例是否也由宽度未生效导致，需要独立复现确认。
- Tk 文件加载失败发生于同进程多次创建 root 还是外部环境变化，需要完整日志和顺序复测。
- 真实指针失败中，窗口位置、映射时序和外部鼠标干扰各占什么影响。
