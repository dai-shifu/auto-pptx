## Context

`src/gui.py` 当前在根窗口按顺序 `pack` 文件区、Sheet 配置、数据预览、映射区和生成按钮。预览区内也先打包 Treeview，再打包横向和竖向滚动条，导致宽度不足时滚动条没有剩余空间；横向滚动条实际位于 Treeview 右侧剩余区域，不能稳定出现在表格底部。

相同 Tk 布局的无窗口实验中，6 个 280px 数据列、300 行数据在 1400px 窗口下两条滚动条均不可见，1800px 时恢复可见；10 行也存在相同问题。行数不是布局触发条件。当前预览包含勾选列、前五个 Excel 列，以及必要时追加的模板列。

映射配置为每行四项且没有独立滚动容器。用户选择上下可调分区方案，取消预览的横向滚动，并通过 tooltip 查看超宽内容。窗口默认 1400×850，最低 1000×600；使用现有 Tkinter/ttk 和 Python 3.11 兼容代码。

## Goals / Non-Goals

**Goals:**

- 支持默认和最低窗口尺寸，顶部配置和底部生成按钮始终可用。
- 预览与映射配置上下可调，映射项增长只扩大内部滚动内容。
- 所有预览列均在可见宽度内，竖向滚动条拥有独立位置。
- 仅对显示不完整的单元格及表头提供完整内容提示。
- 保留数据、Excel 实际行号、手动映射、勾选行为和生成接口。

**Non-Goals:**

- 不引入分页、虚拟表格、后台 Excel 读取或新的 GUI 框架。
- 不优化本次讨论发现的重复 Excel 读取，也不改变模板检测算法。
- 不持久化分区位置，不修改 `config.toml` 格式。
- 不改变既有默认勾选策略；历史规格中默认全选与当前代码全不选的偏差不在本次调整范围。

## Decisions

### 1. 固定外层区域，工作区使用上下可调分区

根窗口使用 `grid`：文件区和 Sheet 配置占固定高度行，工作区所在行设置伸缩权重，底部按钮及状态行固定。文件路径输入框横向伸展；Sheet 配置内部避免固定宽度控件总和超出最低窗口宽度。

工作区使用垂直 `ttk.Panedwindow`，上部为预览，下部为映射配置。首次完成布局后，按约 70%/30% 分配内部高度。预览区最低 180px，映射区最低 100px，包含各自工具栏及边距。窗口缩放和分隔线拖动均将分隔线约束在两区最低高度允许的范围内；有空间时保持用户调整的比例。默认外层尺寸必须让两区最低高度与顶部、底部同时容纳。

`ttk.Panedwindow` 不直接提供经典 `tk.PanedWindow` 的每区 `minsize` 配置，最低高度约束由分隔线位置和尺寸事件管理。尺寸响应需合并相邻事件，并忽略未变化的目标位置，避免递归布局。

替代方案：仅修改 Treeview 内部 `grid` 无法约束映射区；折叠映射区不能持续同时查看两部分；左右分区会压缩已受限的表格宽度。采用用户选定的上下分区。

### 2. 两个区域独立布局和竖向滚动

预览区工具栏在上方，表格容器在下方并随预览区伸缩。容器内 Treeview 占可伸缩列，竖向滚动条占固定列。取消横向滚动条及其连接。上下布局区域各自选择几何管理方式，同一个父容器内不混用 `pack` 和 `grid`。

映射区标题固定，下面是 Canvas、内部映射 Frame 和竖向滚动条。内部 Frame 宽度跟随 Canvas 视口，内容高度更新 `scrollregion`。滚轮处理局限于映射区；在表格上滚轮仍滚动预览，在组合框上保留组合框的交互。处理 Windows/macOS 的 MouseWheel 和 Linux 的 Button-4/Button-5。

映射项按可用宽度排列，最多四列；最低窗口宽度下可降为两列或三列。列名允许截断，组合框保留可操作宽度，长列名可复用 tooltip。调整映射项布局时只移动控件，保留原 `StringVar`、选择值及回调；刷新数据仍遵循 `_explicit_mapping` 的既有优先级。

### 3. 按视口预算分配列宽

勾选列固定 40px。根据 Treeview 实际内宽扣除边框和勾选列，得到数据列宽度预算。最多六个数据列等分预算，每列最大 200px；除整数分配外，宽度不依赖表头或数据长度。预算充足时未使用的空间留在表格右侧，不突破上限。列数改变和视口宽度改变时重新计算，避免扫描数据行。

最低窗口尺寸下数据列目标最小宽度 80px，正常容器几何必须容纳六个数据列。不得依赖默认 `minwidth` 造成列宽总和超过预算；内部计算遇到极小的初始化尺寸时推迟到布局稳定后处理。设置 `stretch=False`，由统一列宽计算控制大小，禁用表头分隔线拖动，防止用户扩大列宽后出现不可访问的列。

更新列宽不重建数据行，也不修改完整单元格值。预览列选择继续调用 `_preview_columns`。旧 `treeview-column-limit` 中禁止追加模板列的文字仅做规格对齐，运行时列选择不变。

替代方案：固定每列 200px 在 1000px 窗口下可能超宽；仅设置 `stretch=True` 难以保证上限和总宽约束；扫描所有行计算最佳宽度没有必要。采用只依赖列数及视口的预算分配。

### 4. 按需展示单个 tooltip

复用一个无边框提示窗口，鼠标进入新的单元格或表头时记住目标，取消旧计时器并隐藏旧提示。停留约 400ms 后，用当前主题字体测量目标完整文字宽度，与实际列宽扣除文字边距后的宽度比较；换行内容只要有不可见部分也视为截断。勾选列、空内容、完整可见的内容不显示提示。

提示展示原始完整文本、自动换行，不截短底层数据。表头与单元格使用各自的主题字体。长文本提示使用受屏幕尺寸约束的窗口，必要时允许在提示中滚动；鼠标从目标进入提示窗口时保持显示，离开二者后关闭。位置限制在可用屏幕内，避免提示遮挡当前目标。

Treeview 竖向滚动、列宽变化、分区拖动、点击、Sheet 或模板列刷新，以及窗口关闭时，均取消待执行回调并隐藏提示；销毁窗口时清理提示窗口和计时器。现有复选框点击绑定保留，新事件绑定不得覆盖既有回调。

只在目标改变时重新安排提示，不在每个 Motion 事件扫描全表或创建窗口。Tooltip 逻辑对 300 行的开销与当前悬停单元格有关，不随总行数增长。

### 5. 以实际 Tk 几何和状态回归验证

列宽分配可以独立验证：零数据列、少于五列、六列、不同视口预算、上限和总宽约束。Tooltip 验证重点是截断判断、移动后的旧回调失效、滚动/刷新后的清理、以及数据值保持完整。

真实 Tk 布局验证涵盖 1400×850 和 1000×600、300 行、长文本、六个预览列、多映射项、窗口反复缩放和分隔线拖到边界。检查控件实际可见状态、列的实际边界、两区最低高度、映射内部滚动及底部生成按钮位置；确认竖向滚动能够到达并勾选最后一行。

支持无显示环境的测试对无法创建 Tk 的情况给出明确跳过原因；实现验收仍必须至少执行一次真实显示或 Xvfb 下的布局验证，不能只依赖模拟控件。记录实际 300 行文件的加载与交互表现，不承诺跨机器的毫秒级阈值。实现提交前运行完整测试套件并提供 GUI 截图。

## Risks / Trade-offs

- [分区拖动可将一侧缩到不可用] → 同时约束用户拖动和窗口缩放时的分隔线位置，并验证最低窗口尺寸。
- [映射组合框和表格争抢滚轮事件] → 作用域局限于当前区域，避免全局绑定劫持滚轮。
- [不同主题和 DPI 下截断判断偏差] → 读取实际字体和单元格边界，预留文本内边距，实测中文及英文。
- [刷新后悬停回调引用已删除行] → 统一清理待执行计时器，显示前重新验证目标有效性。
- [很长的提示超出屏幕] → 限制提示窗口尺寸、换行并允许内部滚动，保留完整内容。
- [300 行加载仍可能受 Excel 读取和模板分析影响] → 本次记录真实耗时；若有明显延迟，再单独提出读取流程优化变更。

## Migration Plan

按外层布局、映射滚动、列宽管理、tooltip 的顺序实施，逐步验证既有状态行为。无配置和数据迁移；回滚时恢复原布局和 GUI 辅助代码即可。实现通过验证后再归档本变更并合并规格。

## Open Questions

无阻塞决策。默认约 70%/30% 分区比例、180px/100px 最低高度和 400ms 悬停延迟在真实 GUI 验证时确认可用性；如调整设计参数，同步更新本设计及相应规格。
