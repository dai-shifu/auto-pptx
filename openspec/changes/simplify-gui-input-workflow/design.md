## Context

`App` 的文件框可编辑，但只有浏览和设置事件会刷新预览。Excel 读取失败只清模板列。成功刷新又默认清空勾选，即使只是换模板。用户确认可舍弃粘贴路径，并要求在无模板列时提前提示。

## Goals / Non-Goals

**Goals:** 让文件路径、预览和勾选对应同一份已载入数据。移除重复读取、重绘和未使用的状态。

**Non-Goals:** 不改映射布局、悬停或检查报告。不引入分页、后台任务、文件监视或工作簿缓存。不改生成模块、模板匹配规则、保存配置优先级或发布方式。

## Decisions

- 保留两个原生「浏览」按钮；路径框只展示选择结果。取消对话框不改状态。Excel 或工作表加载失败时，显示错误并清掉旧预览、模板列选项、基于旧数据的映射控件和勾选。保留已保存及显式设置，待下一次有效加载时按现有优先级使用。
- 用成功读入的数据范围决定是否保留勾选，不能仅凭 Treeview 是否重建判断。换文件、Sheet 或有效标题行时清空；只换模板或映射且数据没变时保留。换模板后若自动识别得到不同标题行，按数据范围变化处理。Excel 实际行号仍是生成选择的依据。
- 每次刷新仅完整读取一次当前表格数据。复用读取结果做现有标题识别和数据切分，保持标题去空格、空值、行号和检测证据规则。文件浏览时的工作表名枚举可以保留，不加跨刷新缓存。检查和生成仍可按各自需要重新读取输入文件。
- 模板列切换前后按现有预览列规则判断是否要重建。可见列相同就保留现有行和滚动位置；不同才更新预览，保留勾选。「全选」仍作用于当前工作表所有数据行。
- 保留 `_current_settings()` 作为检查与生成的共同设置来源。点击生成时校验模板列有效，提示「未确定模板列。请在『模板列』下拉框中选择用于匹配 PPT 模板的 Excel 列。」校验失败不调用 `generate()`，不保存配置。只读检查仍可在未确定模板列时运行。生成模块给其他调用方的回退行为不变。
- 删除只写不读的 `_mapping_from_config`。自动建议只进 `_auto_mapping`；保存配置和手动选择只进入显式覆盖。保留显式「不映射」，不要用缺少选择代替它。

## Risks / Trade-offs

- 粘贴路径不再改变文件 → 始终显示完整路径内容，操作文档使用「浏览」说明换文件。
- 识别标题的读取路径合并可能改变行号或文本 → 复用既有识别和归一化规则，并验证非首行标题的选行结果。
- 拦截无模板列可能被其他校验掩盖 → 测试使用有效文件、Sheet 和勾选行，只让模板列为空。
