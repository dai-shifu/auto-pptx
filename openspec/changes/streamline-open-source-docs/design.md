## Context

软件准备公开协作开发。使用文档需要精简，贡献者也需要了解现行行为、历史决策、验证方法和修改规范。公开文档与内部发布交接材料应有明确边界。

## Goals / Non-Goals

**Goals:** 支持用户快速使用、贡献者独立开发和复现验证，同时将个人运维材料留在本地。

**Non-Goals:** 不改变生成逻辑，不创建远程仓库，不增加 Gitee API 或自动同步工作流。

## Decisions

- CONTRIBUTING 作为协作规范入口，开发文档说明模块职责、生成流程和构建方法；README 链接两者。AGENTS 引用这些公共文档并列出关键行为约束。
- 完整保留 openspec 的目录结构，包括配置、现行规格、活动变更、历史归档、通用验证记录和合成截图。历史方案以现行规格和当前代码为准，不将历史测试数量当作当前结果。
- 原验收记录的个人交接与工具安装描述备份在 .local；公开恢复对应的通用验证结果。个人身份、实际账号与首次发布操作不写进 OpenSpec。
- .codex 等本机技能与设置、根目录运行配置和一次性源码导出工具不受 Git 跟踪。导出工具及其测试位于 .local/tools。
- 导出白名单包含 AGENTS、CONTRIBUTING 和完整 openspec；排除 .local、个人工具配置、运行配置与旧迁移工具路径。为错误列入清单和已跟踪文件保留回归测试。
- 自动 Release 正文保留系统、源码提交、exe 和校验说明，人工发版清单保存在本地手册。

## Risks / Trade-offs

- 历史提案可能与当前行为不同 → 贡献指南说明现行规格、活动变更和归档的用途。
- 完整技术档案可能夹带个人操作信息 → 保留原始记录本地备份，审查后公开通用技术内容。
- 本地工具不会随仓库分发 → 公开应用、测试和构建不依赖这些工具；从公开快照验证完整测试。
